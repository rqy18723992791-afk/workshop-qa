# RAG 问答生成设计说明

> 对应代码：`backend/app/services/chat.py`、`backend/app/routers/chat.py`
> 答辩可讲清的一句话：**先用向量检索找到"哪份文档的哪一节"能回答问题，再把这几段原文编号后交给本地模型，模型只许依据编号资料作答，资料不足就拒答；回答与出处一起返回。**

## 1. 整体链路

```
用户问题
  → bge-m3 向量化
  → Chroma 余弦检索 top-4
  → 相似度 < 0.5？──是──→ 直接拒答（不调用大模型）
                │
                否
  → 拼装参考资料（[1] 文档名（编号）｜章节 + 原文）
  → Qwen2.5-7B（Ollama）生成
  → 若模型判断资料不足 → 输出固定拒答语
  → 返回答案 + 引用来源（文档名 + 原文片段 + 章节）
```

## 2. 参考资料如何拼

每个检索片段编号后放入上下文：

```
[1] 文档：注塑机开机与停机操作规程（EQ-OP-001）｜章节：二、开机前检查
1. 电源与气源：……
2. 冷却水：……
```

**为什么要带文档名和章节**：模型在引用时能写出 `[1]`，前端把 `[1]` 映射回"文档名 + 原文片段"；同时章节路径本身提供了语义线索，减少模型把不同文档的内容张冠李戴。编号从 1 开始严格对应 `sources` 数组的 `index`，前端不需要再做字符串匹配。

## 3. 系统提示词的关键约束

1. 只允许使用【参考资料】，禁止常识和推测补充；
2. 资料不足时**只输出**"知识库中暂无相关记录。"；
3. 保留步骤编号、温度/压力数值和单位；
4. 引用句末标注 `[编号]`，编号必须与资料一致；
5. 不编造资料中没有的报警代码、参数值、操作步骤。

第 2 条是拒答的"生成层"防线，第 5 条针对大模型最容易犯的错——把相似场景的报警代码或数值套到当前问题上。

## 4. 两层拒答策略与实测依据

| 层 | 触发条件 | 行为 | 实测 |
| --- | --- | --- | --- |
| 检索层 | top-1 相似度 < 0.5 | 不调用模型，直接返回拒答 | "如何做红烧肉" 0.436 → 拒答 |
| 生成层 | 模型判断资料不足 | 模型输出固定拒答语 | "注塑机多少钱一台" 检索 0.607（过阈值），模型仍拒答 |

**为什么必须两层**：11-06 阈值校准发现，正向问题最低 0.534，无关问题最高 0.607（"注塑机多少钱一台"属于注塑领域、但知识库没有价格信息），任何单一相似度阈值都无法把两类完全分开。检索层用 0.5 保召回，把"领域相关但无答案"的边界问题交给生成层判断。

生成层拒答时，服务端把 `sources` 置空——避免界面出现"拒答但列了一堆出处"的自相矛盾展示。

## 5. 流式协议（SSE）

`POST /api/chat/stream`，响应 `text/event-stream`，每个 `data:` 是一个 JSON 事件：

| 事件 | 时机 | 字段 |
| --- | --- | --- |
| `meta` | 检索完成、生成开始前 | `route`（local）、`model`、`max_score`、`refused`、`sources[]`（含 `index/doc_title/doc_no/heading_path/score/text`） |
| `delta` | 每生成一小段 | `content` |
| `done` | 生成结束 | `answer`（完整答案）、`refused` |
| `error` | 检索或生成失败 | `message` |

**为什么先发 `meta`**：引用来源在生成开始前就已经确定，先发给前端可以让"出处"与"答案"同时出现，用户不用等生成完才看到依据；如果检索层直接拒答，`meta.refused=true` 且 `sources=[]`，前端可以立即展示拒答卡片。

## 6. 关键参数

| 参数 | 值 | 依据 |
| --- | --- | --- |
| top_k | 4 | 4 段约 500～1000 字，足够回答一个具体操作问题，又不会挤占 7B 模型的 4K 上下文 |
| temperature | 0.1 | 车间问答要求稳定、可复现，不需要创造性 |
| num_ctx | 4096 | 与显存和模型能力匹配；上下文过长会拖慢首字 |
| keep_alive | 30m | 实测冷加载 17 s，驻留后首字延迟 2.1 s |
| 拒答阈值 | 0.5 | 11-06 校准，见《文档切分与入库设计说明》 |

## 7. 实测结果（2026-11-05 深夜）

1. **可回答问题**："注塑机开机前需要检查什么"
   - 答案覆盖电源/气源、冷却水、液压油、安全装置、模具、交接记录六类检查，数值与文档一致；
   - 引用 `[1]`（EQ-OP-001 二、开机前检查）、`[2]`（EQ-OP-003 二、开机前安全确认）；
   - 非流式 max_score 0.783；流式首字 2.13 s、总耗时 6.45 s、259 个增量事件。
2. **不可回答问题**："如何做红烧肉"
   - 检索 0.436 < 0.5，直接拒答，答案严格为"知识库中暂无相关记录。"，`sources=[]`。
3. **边界问题**："注塑机多少钱一台"
   - 检索 0.607 过阈值，模型依据提示词拒答，`sources=[]`。

## 8. 取舍与后续

- **不用云端模型做主回答**：本地优先是产品卖点（数据不出厂），云端只在 11-13 端云路由中作为低置信兜底。
- **不做答案后处理校验**：如逐句核对引用编号是否真实存在，属于可选增强；当前提示词 + 小规模知识库下引用正确率已满足验收。
- **前端展示留到 11-08**：SSE 事件协议已经稳定，前端只需消费 `meta/delta/done` 三类事件。
- **拒答阈值精调**：需要更多真实问题样本，11-07 用 20～30 条问句扩充校准集后再定稿。

## 9. 答辩可能被问到的问题

- **模型会不会拿着不相关的资料硬答？** 会，所以先设检索阈值挡住低相似度问题；过阈值但资料仍不足的情况，由提示词第 1、2 条约束，实测"注塑机多少钱"能正确拒答。
- **为什么不让模型自己决定是否查资料？** 车间场景要求确定性，每次都检索成本低（热态 0.5 s），比让模型"决定要不要检索"更可控。
- **引用编号会不会对不上？** `sources.index` 与提示词里的编号严格同源生成，前端按 index 映射，不做自然语言匹配；模型若引用不存在的编号，属于待增强的校验点。
