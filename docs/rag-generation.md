# RAG 问答生成设计说明

> 对应代码：`backend/app/services/chat.py`、`backend/app/services/cloud.py`、`backend/app/routers/chat.py`、`frontend/src/components/ChatView.vue`
> 答辩可讲清的一句话：**先用向量检索找到「哪份文档的哪一节」能回答问题，再把这几段原文编号后交给本地模型，模型只许依据编号资料作答，资料不足就拒答；回答与出处一起流式返回，本地答不了时按配置升级云端。**

## 1. 整体链路

```
用户问题
  → bge-m3 向量化
  → Chroma 余弦检索 top-4
  → max_score < 0.6 ? ──是──→ route_mode=auto ? 云端直接答 : 本地拒答
                │
                否
  → 拼装参考资料（[1] 文档名（编号）｜章节 + 原文）
  → Qwen2.5-7B（Ollama）流式生成
  → 模型输出拒答语 ? ──是──→ route_mode=auto ? 带资料升级云端 : 本地拒答
                │
                否
  → 返回答案 + 引用来源（文档名 + 原文片段 + 章节）
```

端云切换的完整决策树、缓冲拒答和云端提示词边界见 [routing.md](routing.md)；本文聚焦本地 RAG 生成本身。

## 2. 参考资料如何拼

每个检索片段编号后放入上下文：

```
[1] 文档：注塑机开机与停机操作规程（EQ-OP-001）｜章节：二、开机前检查
1. 电源与气源：……
2. 冷却水：……
```

**为什么要带文档名和章节**：模型在引用时能写出 `[1]`，前端把 `[1]` 映射回「文档名 + 原文片段」；同时章节路径本身提供了语义线索，减少模型把不同文档的内容张冠李戴。编号从 1 开始严格对应 `sources` 数组的 `index`，前端不需要再做字符串匹配。

## 3. 系统提示词的关键约束

1. 只允许使用【参考资料】，禁止常识和推测补充；
2. 资料不足时**只输出**「知识库中暂无相关记录。」；
3. 保留步骤编号、温度/压力数值和单位；
4. 引用句末标注 `[编号]`，编号必须与资料一致；
5. 不编造资料中没有的报警代码、参数值、操作步骤。

第 2 条是拒答的「生成层」防线，也是路由判断「本地置信不足」的信号；第 5 条针对大模型最容易犯的错——把相似场景的报警代码或数值套到当前问题上。

## 4. 两层拒答 + 一层路由

| 层 | 触发条件 | 行为 | 实测 |
| --- | --- | --- | --- |
| 检索层 | top-1 相似度 < 0.6 | 不调用本地模型；auto 模式直接上云，kb_only 直接拒答 | 「如何做红烧肉」0.4242 → 拒答 |
| 生成层 | 本地模型判断资料不足 | 输出固定拒答语；auto 模式缓冲后带资料升级云端 | 「螺杆磨损到什么程度要更换」检索 0.6589，本地拒答后切云端 |
| 路由层 | 云端也拒答 / 云端不可用 | 返回云端拒答或回退本地拒答，`sources=[]` | 云端失败发 `error`，不伪装成本地答案 |

**为什么必须两层**：30 条问句校准（见 [retrieval.md](retrieval.md)）显示，正向最低 0.675、负向最高 0.522，0.6 能分开明确无关与明确可答；但「注塑相关、手册没写」的灰区问题分数可能落在 0.6 附近，检索层挡不住，必须由生成层判断资料是否足够。

生成层拒答时，服务端把 `sources` 置空——避免界面出现「拒答但列了一堆出处」的自相矛盾展示；升级云端后来源换成云端实际使用的资料。

## 5. 流式协议（SSE）

`POST /api/chat/stream`，响应 `text/event-stream`，每个 `data:` 是一个 JSON 事件：

| 事件 | 时机 | 字段 |
| --- | --- | --- |
| `meta` | 检索完成、生成开始前 | `route`、`route_reason`、`model`、`max_score`、`min_sim`、`refused`、`grounded`、`sources[]`（含 `index/doc_title/doc_no/heading_path/score/text`） |
| `route` | 本地切云端时 | 新 `route`、`route_reason`、`model`、`grounded`、`sources` |
| `delta` | 每生成一小段 | `content` |
| `done` | 生成结束 | `answer`（完整答案）、`route`、`model`、`refused`、`grounded`、`sources` |
| `error` | 检索或生成失败 | `message` |

**为什么先发 `meta`**：引用来源在生成开始前就已经确定，先发给前端可以让「出处」与「答案」同时出现，用户不用等生成完才看到依据；如果检索层直接拒答，`meta.refused=true` 且 `sources=[]`，前端可以立即展示拒答卡片。

**为什么 `done` 要重发完整答案**：网络分块可能丢字或重复，前端以 `done.answer` 为准覆盖增量，保证最终文本完整。

## 6. 关键参数

| 参数 | 值 | 依据 |
| --- | --- | --- |
| top_k | 4 | 4 段约 500～1000 字，足够回答一个具体操作问题，又不会挤占 7B 模型的 4K 上下文 |
| temperature | 0.1 | 车间问答要求稳定、可复现，不需要创造性 |
| num_ctx | 4096 | 与显存和模型能力匹配；上下文过长会拖慢首字 |
| keep_alive | 30m | 模型常驻，避免每次冷加载 10～30 s |
| 拒答阈值 | 0.6 | 30 条问句校准的中点，见 [retrieval.md](retrieval.md) |
| 云端超时 | 60 s | `CLOUD_TIMEOUT`，超时抛 `CloudUnavailable`，不无限等待 |

## 7. 实测结果（2026-11-05，阈值 0.6）

完整 JSON 留痕在 `docs/evidence/`。

1. **可回答问题**：「注塑机开机前需要检查什么？」
   - top-1 **0.7833**，命中 `EQ-OP-001`、`EQ-OP-003`、`PM-D-001`；
   - 答案覆盖电源/气源、冷却水、液压油、安全装置、模具、交接记录六类检查，数值与文档一致；
   - 引用 `[1]`（EQ-OP-001 二、开机前检查）、`[2]`（EQ-OP-003 二、开机前安全确认）；
   - 首字 1.0 s，本地路径，未上云。见 [evidence/route-local.json](evidence/route-local.json)。
2. **本地拒答、云端升级**：「注塑机螺杆磨损到什么程度必须更换？请给出判断标准和检测方法」
   - top-1 **0.6589** 过阈值，但资料里没有磨损量化标准；
   - 本地先生成，判断资料不足 → 缓冲拒答 → `route` 事件切云端；
   - 云端给出磨损量、螺棱间隙、表面损伤等通用判断标准，标【通用建议】与「需现场确认」，未编造厂家参数；
   - 事件序列 `meta → route(cloud) → delta → done`，模型 `deepseek-chat`，首字 3.3 s。见 [evidence/route-cloud.json](evidence/route-cloud.json)。
3. **完全无关问题**：「如何做红烧肉？」
   - 检索 **0.4242** < 0.6；auto 模式把问题发给云端，云端判断与注塑无关，输出固定拒答语；
   - `refused=true`，`sources=[]`，界面显示「已拒答」。见 [evidence/route-refusal.json](evidence/route-refusal.json)。

## 8. 取舍与后续

- **本地优先**：数据不出厂是产品卖点；云端只在低置信时兜底，正常操作问题不产生费用。
- **拒答检测靠固定前缀**：简单、可解释、零额外模型；换模型需回归测试拒答措辞。
- **不做答案后处理校验**：如逐句核对引用编号是否真实存在，属于可选增强；当前提示词 + 小规模知识库下引用正确率已满足验收。
- **前端已消费 `meta/route/delta/done` 四类事件**：引用卡片、路由标签、耗时统计都已接通，见 [frontend.md](frontend.md)。
- **阈值会随文档变化**：换一批手册需重跑 `backend/scripts/calibrate.py`，不把 0.6 当永久常数。

## 9. 答辩可能被问到的问题

- **模型会不会拿着不相关的资料硬答？** 会，所以先设检索阈值挡住低相似度问题；过阈值但资料仍不足的情况，由提示词第 1、2 条约束，本地拒答后还可升级云端复核。
- **为什么不让模型自己决定是否查资料？** 车间场景要求确定性，每次都检索成本低（热态 0.5 s），比让模型「决定要不要检索」更可控。
- **引用编号会不会对不上？** `sources.index` 与提示词里的编号严格同源生成，前端按 index 映射，不做自然语言匹配；模型若引用不存在的编号，属于待增强的校验点。
- **云端答案和本地答案会不会矛盾？** 云端收到的是同一批检索片段 + 原问题，提示词要求资料优先；资料不足时才用【通用建议】并标注，不会把通用经验冒充厂内规程。
