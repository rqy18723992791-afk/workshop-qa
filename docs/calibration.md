# 检索拒答阈值校准记录

> 对应代码：`backend/scripts/calibrate.py`、`backend/app/services/kb.py`
> 结论：**检索阈值取 0.6**（余弦相似度，`score = 1 - 距离`）。30 条问句中
> 15 条可回答问题全部通过，8 条完全无关问题全部被挡住；正负样本之间存在
> 0.522～0.675 的安全间隔，阈值取间隔中点，两侧各留约 0.075 余量。

## 1. 为什么要校准

RAG 的第一道防线是检索闸门：相似度低于阈值就认定"知识库没有相关内容"，
不调用大模型。阈值太低会把无关问题放进来，让模型拿着不相关片段硬答；
阈值太高会把问法不同但确实有答案的问题挡在外面。这个阈值不能拍脑袋，
必须用一批标注过的问句实测。

## 2. 校准集设计（30 条）

| 类别 | 数量 | 定义 | 期望 |
| --- | --- | --- | --- |
| positive | 15 | 知识库里有明确答案的注塑问题 | 通过闸门 |
| negative | 8 | 与注塑完全无关的问题 | 被闸门挡住 |
| gray | 7 | 属于注塑领域，但知识库没有答案 | 可过闸门，由生成层/云端拒答 |

- positive 覆盖操作、点检、保养、五类故障案例、安全、工艺参数，避免只测一种文档；
- negative 包含生活、天气、文学、体育、编程、影视、手机、股票，覆盖不同语义空间；
- gray 专门收集"领域相关但无答案"的边界问题，例如价格、品牌、薪酬、认证。

检索配置：bge-m3 embedding，Chroma 余弦距离，`top_k=4`，取 top-1 分数作为
`max_score`。完整明细见 [calibration-data.json](calibration-data.json)。

## 3. 实测结果

| 类别 | 最低分 | 平均分 | 最高分 |
| --- | --- | --- | --- |
| positive（15） | 0.6752 | 0.7537 | 0.8174 |
| negative（8） | 0.2369 | 0.3776 | **0.5219** |
| gray（7） | 0.4355 | 0.5749 | 0.6173 |

关键观察：

1. **正负样本存在清晰间隔**：最高无关分 0.5219（"我的手机屏幕碎了怎么办"），
   最低可答分 0.6752（"加热圈正常电阻是多少"），中间没有样本。
2. **旧阈值 0.5 会漏放**："我的手机屏幕碎了怎么办" 0.5219 > 0.5，会被当成
   "相关内容"送进模型；虽然生成层大概率拒答，但白白多一次推理，且增加编造风险。
3. **gray 问题跨在阈值两侧**：价格 0.607、螺杆磨损 0.617、能耗 0.603、月薪 0.613
   会过闸门，品牌对比 0.436、排行榜 0.567、出口认证 0.581 会被挡住。这说明
   单一相似度无法表达"领域相关但无答案"，必须保留生成层拒答与端云路由。

## 4. 阈值选择

候选阈值从 0.30 到 0.70 逐 0.001 扫描，以"positive 通过率 + negative 挡住率"
计算准确率。扫描得到的最高准确率阈值是 0.522（刚好卡在最高负样本之上），
但这样贴着样本走，换一批问句就容易失效。

因此采用更稳的规则：**正负样本存在间隔时，取间隔中点**。

```
(0.5219 + 0.6752) / 2 = 0.59855  →  取 0.6
```

| 阈值 | positive 通过 | negative 误放 | 说明 |
| --- | --- | --- | --- |
| 0.5（旧） | 15/15 | 1/8 | "手机屏幕碎了" 0.5219 被误放 |
| 0.522（最高准确率） | 15/15 | 0/8 | 贴边，无余量 |
| **0.6（采用）** | **15/15** | **0/8** | 两侧各留约 0.075 |
| 0.675（最低正样本） | 15/15 | 0/8 | 贴边，问法稍变就可能漏检 |

0.6 不是"数学最优"，而是"工程上更稳"：它不改变当前 30 条问句的判定结果，
同时给同义改写、口语化提问留出空间。若后续真实用户问句出现漏检，优先补
校准集后重跑脚本，而不是凭感觉下调。

## 5. 与端云路由的配合

- `score ≥ 0.6`：本地知识库作答；
- `score < 0.6` 且开启智能协同：直接升级 DeepSeek，界面标注"检索相似度不足"；
- `kb_only` 严格模式：直接拒答，不调用云端；
- 过了 0.6 但本地模型判断资料不足：本地拒答 → 自动升级云端复核；
- 云端也判断与注塑无关：返回统一拒答语，`sources=[]`。

这样阈值只负责"要不要查知识库"，"答不答、怎么答"由生成层和路由层共同决定，
避免把产品正确性全押在一个相似度数字上。

## 6. 复现方式

```bash
cd backend
.venv/Scripts/python.exe scripts/calibrate.py    # Windows
# Linux: .venv/bin/python scripts/calibrate.py
```

脚本会重新计算全部 30 条问句的分数，覆盖写入 `docs/calibration-data.json`，
并打印 positive/negative/gray 的统计与推荐阈值。

## 7. 取舍与后续

- **样本量仍偏小**：30 条足以支撑演示和当前知识库，但不是统计意义上的大样本；
  上线前应收集真实车间问句，扩到 100 条以上再校准一次。
- **只校准 top-1 分数**：top-k 的平均分、分差也可作为特征，但会增加解释成本，
  当前知识库规模下没有必要。
- **阈值与 embedding 模型绑定**：换 embedding 模型（如从 bge-m3 换成其他）
  必须重新跑本脚本，分数分布不可直接迁移。
