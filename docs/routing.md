# 端云协同路由设计说明

> 对应代码：`backend/app/services/chat.py`、`backend/app/services/cloud.py`、`backend/app/routers/chat.py`
> 答辩可讲清的一句话：**默认在本地答；检索分数低于 0.6 或本地模型明确说「资料不足」时，自动把同一批资料交给 DeepSeek 复核；界面始终告诉用户这次走的是哪条路、为什么。**

## 1. 为什么需要路由

只本地、只云端都不成立：

- **只本地**：7B 小模型 + 15 份手册，能覆盖的操作问题有限。问「螺杆磨损到什么程度要换」，手册里没有量化标准，本地只能拒答，用户体验差。
- **只云端**：车间网络可能不稳定，设备参数、工艺数据上传云端有保密顾虑；每次调用还有成本和延迟。

所以做「本地优先、云端兜底」：**能本地答的绝不上云，本地答不了的才升级**。这既是产品卖点（数据不出厂），也是可用性保障。

## 2. 决策树

路由发生在检索之后、生成之前/之中，分四种情况：

```
                检索 top-4
                    │
        max_score >= 0.6 ?
          │                     │
         是                     否
          │                     │
   本地模型生成           route_mode = auto ?
     │        │              │          │
  正常答案  输出拒答语         是         否(kb_only)
     │        │              │          │
  本地结束    │           云端直接答    本地拒答
             │           （不带资料）
       route_mode = auto ?
          │          │
         是          否
          │          │
   带资料升级云端   本地拒答
```

用文字说清四条路径：

| 情况 | 行为 | 界面 |
| --- | --- | --- |
| 检索命中（≥0.6），本地正常答 | 本地生成，带引用 | 绿色「本地模型 · 知识库作答」 |
| 检索命中，本地输出拒答语 | 缓冲拒答，改走云端（带资料） | 先显示本地，收到 `route` 事件后切换为蓝色「云端模型 · 通用建议」 |
| 检索不命中（<0.6），auto 模式 | 直接把问题发云端（不带资料） | 蓝色「云端模型」，原因写明分数低于阈值 |
| 检索不命中，`kb_only` 模式 | 本地固定拒答，不联网 | 绿色「本地模型 · 已拒答」 |

`route_mode` 可由前端按次传入，也支持 `.env` 的 `ROUTE_MODE` 设默认值。

## 3. 关键实现细节

### 3.1 什么算「本地模型自评置信不足」

没有读 logprobs，也没有额外的置信度模型。做法是**检测本地输出是否以固定拒答语开头**：

```python
REFUSAL = "知识库中暂无相关记录。"
def _is_refusal(text): return text.strip().startswith("知识库中暂无相关记录")
```

提示词要求资料不足时必须只输出这句话。这个方案简单、可解释，但依赖模型遵循指令；如果模型换了拒答措辞，会漏判。当前 Qwen2.5-7B 在实测中稳定遵循。更稳的做法是让模型输出结构化 JSON（`{"enough": false}`），代价是流式输出变复杂，暂未采用。

### 3.2 为什么本地拒答要「先缓冲再决定」

流式生成时，如果模型先吐出「知识库中暂无相关记录」，前端会先显示拒答卡片，几百毫秒后又突然变成云端答案，体验很差。所以本地流式输出先进入缓冲区：

- 只要还是拒答语的前缀，就继续攒、不发给前端；
- 一旦和拒答语分叉，确认是正常答案，把缓冲区一次性发出，之后正常流式；
- 如果完整输出就是拒答语，丢弃缓冲，发 `route` 事件切云端。

这样用户要么看到完整的本地答案，要么直接看到云端答案，不会看到「拒答 → 又 answer」的闪烁。

### 3.3 云端提示词的三条边界

云端不是「什么都答」的通用聊天，提示词做了三重限制：

1. **只答注塑相关**：注塑机、工艺、模具、维护、车间安全；无关问题只输出固定拒答语。
2. **资料优先，允许通用建议**：参考资料能答的部分优先用并标 `[n]`；资料不足时用【通用建议】开头补充工程经验，并提示「需现场确认」；不得编造报警代码、型号参数、厂家数据。
3. **安全提醒**：涉及拆机、带电、高温，必须提醒断电挂牌、冷却、持证操作。

第一版提示词要求「资料不足就拒答」，结果「螺杆磨损」这种领域相关但手册没写的问题也被云端拒了——这不是路由想要的。后来改成「只有完全无关才拒答，领域相关问题允许【通用建议】」，才达到「本地答不了、云端能补充」的设计目的。

### 3.4 云端失败怎么办

`cloud.py` 把网络错误、超时、非 200、空响应统一抛 `CloudUnavailable`。路由层捕获后：

- 非流式：回退为本地拒答，并在结果里带 `cloud_error`；
- 流式：发 `error` 事件，前端显示错误卡片，不会把半截答案当成完整答案。

不会静默吞掉错误，也不会把云端失败伪装成本地答案。

## 4. SSE 协议

`POST /api/chat/stream` 返回 `text/event-stream`，事件顺序：

```
meta   → 检索完成：初始路由、模型、分数、阈值、来源
route  → 仅切换云端时出现：新路由、原因、新模型
delta  → 正文增量（可能很多条）
done   → 完整答案、最终路由、是否拒答、来源
error  → 失败信息
```

`meta` 里的 `route` 是**初始**路由，`done` 里的才是最终路由；前端以 `route` 事件更新标签，以 `done` 落库/展示最终状态。这样即使中途切换，界面和实际路径也一致。

## 5. 实测记录（2026-11-05，阈值 0.6）

原始数据在 [evidence/route-local.json](evidence/route-local.json)、[evidence/route-cloud.json](evidence/route-cloud.json)、[evidence/route-refusal.json](evidence/route-refusal.json)。

### 5.1 本地路径

- 问题：注塑机开机前需要检查什么？
- 检索：top-1 **0.7833** ≥ 0.60，命中 `EQ-OP-001`、`EQ-OP-003`、`PM-D-001`
- 路由：`local`，模型 `qwen2.5:7b-instruct-q4_K_M`
- 结果：7 条检查项，数值正确，引用 [1][2]；首字 1.0 s，未上云

### 5.2 云端升级路径

- 问题：注塑机螺杆磨损到什么程度必须更换？请给出判断标准和检测方法
- 检索：top-1 **0.6589**，过阈值，命中保养标准（但没有螺杆磨损量化标准）
- 过程：本地先生成，判断资料不足 → 缓冲拒答 → `route` 事件切云端
- 路由：`cloud`，模型 `deepseek-chat`，原因「本地模型判断资料不足，已升级云端复核」
- 结果：给出磨损量、螺棱间隙、表面损伤等通用判断标准，标注【通用建议】与「需现场确认」，未编造具体厂家参数；首字 3.3 s
- 事件序列：`meta → route->cloud → done`，证明切换真实发生

### 5.3 无关问题拒答

- 问题：如何做红烧肉？
- 检索：0.4242 < 0.60
- 路由：auto 模式升级云端，云端判断与注塑无关，输出固定拒答语
- 结果：`refused=true`，`sources=[]`，界面显示「已拒答」，不列任何出处

## 6. 隐私与成本边界

- **本地路径**：问题、检索、生成全在本机，不出厂。
- **云端路径**：只发送「用户问题 + 检索到的片段（仅本地判断资料不足时）」，不上传整个知识库、不上传文档原文件。
- **无命中直接上云**：只发送问题本身，不发送资料。
- 云端调用有 token 成本；路由把云端限制在低置信场景，正常操作问题不产生费用。

这些边界应写进给工厂的部署说明；当前 README 和界面隐私提示已标注「仅低置信问题按配置升级云端」。

## 7. 取舍与后续

| 选择 | 取舍 |
| --- | --- |
| 用拒答语判断置信 | 零额外模型、可解释；依赖指令遵循，换模型需回归测试 |
| 云端允许通用建议 | 覆盖手册外问题；必须明确标注，避免用户把通用经验当厂内规程 |
| 不做逐 token 置信 | 实现简单、延迟低；未来可加 logprob 阈值作为第二信号 |
| 失败回退拒答 | 不编造、不静默；用户体验略硬，但安全 |

## 8. 答辩可能被问到的问题

- **怎么证明真的切了云端？** SSE 里有 `route` 事件，`done.route=cloud`、`model=deepseek-chat`；原始 JSON 留痕在 `docs/evidence/`，界面标签也会从「本地模型」变成「云端模型」。
- **云端会不会把厂里数据泄露？** 只发问题和必要片段，不发全库；部署时可在 `.env` 设 `ROUTE_MODE=kb_only` 完全禁用云端。
- **为什么不在检索分数 0.55 时也上云？** 0.55 落在校准的负向高分附近，可能是无关问题，上云既费钱又可能被云端拒；当前策略是「低于 0.6 直接上云，不问本地」，高于 0.6 先让本地判断资料是否足够。
- **本地拒答但云端也拒答怎么办？** 返回云端拒答，来源置空；界面显示「知识库中暂无相关记录」，不会硬编一个答案。
