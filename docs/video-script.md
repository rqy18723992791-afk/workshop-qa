# 演示视频脚本（5–8 分钟）

> 规格：1920×1080 或更高，横屏，录屏 + 旁白；无需出镜。
> 目标：让评委在 8 分钟内看清「痛点 → 本地问答 → 拒答 → 端云路由 → 诊断向导 → 处置单 → MCP → 总结」。
> 开头队伍信息为占位，录制前替换。

## 0. 录制前检查（不录进视频）

- [ ] Ollama 已启动，`qwen2.5:7b-instruct-q4_K_M`、`bge-m3` 已拉取
- [ ] FastAPI 已启动，`/health` 返回 `cloud_configured=true`、`retrieval_min_sim=0.6`
- [ ] 知识库已导入：15 份文档 / 123 切片
- [ ] `backend/.env` 已配置 DeepSeek Key，云端问题提前试一次，确认能触发 `route→cloud`
- [ ] 浏览器缩放 110%，隐藏书签栏，关闭无关标签页
- [ ] 问答页点「清空」，诊断页点「重新诊断」，知识库页回到顶部
- [ ] 录屏软件 1080p 60fps（30fps 亦可），麦克风试音
- [ ] 准备一个终端窗口，字号调大（18–20pt），用于 MCP 演示

## 1. 分镜脚本

### 00:00–00:35 开场（35 s）

**画面**：标题页 / 校园或实验室空镜（可选）→ 切到「车间智答」首页。

**旁白**：

> 大家好，我们是【学校名称】【团队名称】，团队成员【成员姓名 1、2、3】，指导老师【指导老师姓名】。
> 我们带来的作品是「车间智答」——面向智能制造一线的本地化 AI 知识与故障排查助手。

**字幕**：作品名、队伍信息、赛事名称。

---

### 00:35–01:25 痛点（50 s）

**画面**：车间/注塑机素材（可用免费素材或静态图）→ 手册、点检表、微信群截图示意。

**旁白**：

> 注塑车间里，设备手册、点检标准、故障案例、安全规程往往散落在 PDF、纸质文件和老师傅的经验里。
> 新人遇到 A-101 温度报警，第一反应是翻手册、问师傅、在群里发消息——慢，而且每个人说法不一样。
> 直接问通用大模型又有两个问题：设备参数和工艺数据出了厂；模型还会一本正经地编造报警代码和参数。
> 我们需要一个「答得快、答得准、答错了能追责」的系统。

---

### 01:25–02:20 方案总览（55 s）

**画面**：切到项目首页，镜头缓慢扫过顶栏、问答区、右侧链路监视；可叠加架构简图。

**旁白**：

> 车间智答的做法是：把厂内文档切分、向量化，存进本地 Chroma；
> 提问时先用 bge-m3 检索最相关的四段资料，再交给本地 Qwen2.5-7B 生成，答案必须带引用。
> 资料不足时明确拒答；如果问题确实属于注塑领域、只是手册没写，系统会自动升级 DeepSeek，并在界面上标出这次走的是云端。
> 另外，温度异常这类有固定排查路径的故障，我们做了一套确定性的诊断状态机，走完直接生成可打印的处置单。
> 整套系统可以完全离线运行，数据不出厂。

**字幕**：本地优先 / 回答可溯源 / 端云协同 / 确定性诊断。

---

### 02:20–03:40 演示一：本地问答与引用（80 s）

**画面**：问答页，点击示例卡「开机前检查」，等待流式答案。

**操作**：点「开机前检查」→ 答案逐字出现 → 右侧「链路监视」显示 top1 0.78、阈值 0.60、本地模型 → 向下滚动到引用卡片 → 点击正文 `[1]`，引用卡片高亮展开。

**旁白**：

> 我们问一个手册里明确写了的问题：注塑机开机前需要检查什么。
> 可以看到答案在逐字流式输出，右侧同时显示检索最高相似度 0.78，高于阈值 0.60，所以走本地模型。
> 答案里的 [1]、[2] 可以点击，下面就是 EQ-OP-001 的原文片段，文档名、编号、章节、相似度都在。
> 这条回答从检索到生成全部在本机完成，没有发出任何数据。

**画面**：清空对话，输入「如何做红烧肉？」→ 等待拒答。

**旁白**：

> 再问一个和车间无关的问题。检索相似度只有 0.42，低于阈值，系统明确拒答「知识库中暂无相关记录」，并且不列任何出处——不知道就是不知道，不编。

**字幕**：拒答阈值 0.6，30 条问句校准。

---

### 03:40–04:50 演示二：端云协同路由（70 s）

**画面**：输入「注塑机螺杆磨损到什么程度必须更换？请给出判断标准和检测方法」。

**操作**：发送 → 先看到「本地模型」标签 → 短暂后标签变蓝为「云端模型 · 通用建议」，右侧原因变为「本地模型判断资料不足，已升级云端复核」→ 答案出现【通用建议】和「需现场确认」。

**旁白**：

> 这个问题手册里只写了保养周期，没有磨损量的量化标准。检索分数 0.66，过了阈值，但本地模型判断资料不足，输出了拒答语。
> 注意界面：标签从绿色的「本地模型」变成了蓝色的「云端模型」，右侧写明原因是「本地模型判断资料不足，已升级云端复核」。
> 云端给的是通用工程经验，所以标了【通用建议】和「需现场确认」，没有编造具体厂家的参数。
> 这就是我们的端云协同：能本地答的绝不上云，本地答不了的才升级，而且用户始终知道这次走的是哪条路、为什么。

**字幕**：本地 0.78 不上云 / 云端 0.66 触发升级 / 只发送问题与必要片段。

---

### 04:50–06:10 演示三：故障排查向导与处置单（80 s）

**画面**：切到「故障排查」→ 点「开始诊断」。

**操作**：依次选择：
1. 已停机、断电、挂牌并冷却
2. 单个温区持续下降、加热不足
3. 35～45 Ω（正常范围）
4. 端子干净、紧固、无烧蚀
5. 偏差在 ±3 ℃ 以内
6. 不导通或指示灯不亮

每步停留 2–3 秒，展示「手册依据」折叠区；最后生成处置单，滚动展示排查过程、结论、处置建议、安全提示、依据出处；点「打印处置单」，展示 A4 预览。

**旁白**：

> 接下来是故障排查向导。我们选料筒温度异常 A-101，从安全确认开始，系统按手册的排查顺序一步步追问。
> 每一步都给出原文依据，比如加热圈额定 3.5 千瓦、冷态电阻 35 到 45 欧，用户不用凭感觉选。
> 走完六步，系统生成一张处置单：故障现象、排查过程、结论、处置建议、安全提示和全部出处。
> 结论是固态继电器损坏，需要更换；处置单可以直接打印成 A4，也可以下载 Markdown 交给设备科。
> 这条链是状态机，不是让大模型自由发挥——同样的输入一定得到同样的结论，每一步可回退、可追责。

**字幕**：12 节点 / 11 结论 / 每步带手册依据 / 可回退 / A4 打印。

---

### 06:10–07:00 演示四：MCP 与知识库管理（50 s）

**画面**：切到终端，运行：

```bash
backend/.venv/Scripts/python.exe backend/scripts/test_mcp_client.py
```

展示输出：`search_knowledge`、`list_documents`、`has_relevant=True max_score=0.8078`、`documents=15`。

**旁白**：

> 知识库检索还封装成了 MCP 工具。任何支持 MCP 的客户端，比如 Claude Desktop 或 IDE，都能直接发现并调用 search_knowledge 和 list_documents。
> 这样这套厂内知识库不只能服务网页，也能被其他 AI 应用复用。
> 最后看一眼知识库管理：15 份文档、123 个切片，支持上传、删除、重建索引，还有一个检索测试台，可以现场看每个问题的相似度。

**画面**：切到知识库页，展示统计卡、文档表、检索测试台。

---

### 07:00–07:45 技术亮点与总结（45 s）

**画面**：回到首页，叠加四个关键词；最后标题页。

**旁白**：

> 最后总结一下我们的技术亮点：
> 第一，本地优先的 RAG，答案带原文出处，资料不足明确拒答；
> 第二，端云协同路由，低置信自动升级，路径和原因对用户可见；
> 第三，确定性的故障诊断状态机，输出可打印的结构化处置单；
> 第四，知识库检索 MCP 工具化，能被其他 AI 应用复用。
> 对工厂来说，它让新人少走弯路、让老师傅的经验沉淀下来，也让设备数据留在厂内。
> 以上就是「车间智答」，谢谢观看。

**字幕**：仓库地址 `github.com/rqy18723992791-afk/workshop-qa`；团队信息；谢谢。

## 3. 录制建议

- **一镜到底优先**：问答和诊断都是真实交互，切太多会像 PPT；只在终端和浏览器之间切一次。
- **等待时间处理**：本地首字约 0.2–1 s，云端约 2–3 s，不要剪掉，正好证明「真的在跑」；如果超过 8 秒，后期 2 倍速并加字幕「云端生成中」。
- **失败兜底**：云端问题提前试跑；若现场网络不稳，改用 `ROUTE_MODE=auto` 且提前缓存一次成功录屏，或把云端段落改为讲解 `docs/evidence/route-cloud.json` 的录屏。
- **字幕**：关键数字加字幕——0.78 / 0.60 / 0.66 / 6 步 / 0.8078。
- **画面**：1080p 以上，浏览器缩放 110%，终端字号 18–20pt，鼠标移动放慢。
- **旁白**：按稿但不必逐字；每段先说完再看操作，避免「边点边说」导致节奏乱。
