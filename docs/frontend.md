# 前端工程设计说明

> 对应代码：`frontend/src/App.vue`、`components/ChatView.vue`、`components/DiagnosisView.vue`、`components/KnowledgeView.vue`、`style.css`
> 答辩可讲清的一句话：**不引 UI 框架，用一套 CSS 设计令牌把「工业现场」做成深色高对比界面；三个视图共享同一套状态与 SSE 协议，问答、排查、知识库管理在一个页面里完成，并且能直接打印成纸质处置单。**

## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Vue 3 `<script setup>` + TypeScript strict | 组合式 API 适合把 SSE、会话、检索这些过程拆成清晰的小函数；类型与后端字段一一对应 |
| 构建 | Vite | 冷启动快，构建产物小；开发时 `/api` 代理到 8000，生产由 FastAPI 直接托管 `dist` |
| UI 框架 | **无** | 比赛要求「前端工程」可展示；引 Element Plus 会让界面千篇一律，且包体大。自建组件更能体现设计能力 |
| Markdown | marked + DOMPurify | 模型输出是 Markdown；DOMPurify 在渲染前清洗，防 XSS |
| 图标 | 自绘 `Icon.vue`（内联 SVG） | 不引图标库，按需 20 余个图标，体积极小 |
| 状态管理 | 组件内 `ref/reactive` + `KeepAlive` | 页面规模不需要 Pinia；三个视图各自持有状态，切页不丢问答和诊断进度 |

## 2. 页面结构

```
App.vue（外壳）
├─ 顶栏：品牌 / 三个导航 / 本地引擎与云端状态灯
├─ main：<KeepAlive><component :is="当前视图"/></KeepAlive>
│   ├─ ChatView        智能问答
│   ├─ DiagnosisView   故障排查
│   └─ KnowledgeView   知识库管理
└─ 页脚：数据不出厂 · 离线可用 · 回答可溯源 · 版本 · 开源仓库
```

- 路由用 `location.hash`（`#chat/#diag/#kb`）而不是 vue-router：三个页面、无嵌套、无鉴权，hash 足够且刷新可恢复。
- `KeepAlive` 让切走再切回时保留对话、诊断会话和检索测试结果；演示时可以在问答和知识库之间来回切换，不丢上下文。
- 顶栏每 30 秒轮询 `/health`，用两个状态灯告诉观众「本地引擎是否在线」「DeepSeek 是否配置」，避免演示时后端掉线却看不出来。

## 3. 设计系统

`style.css` 顶部定义一套令牌，所有组件只引用变量，不写死颜色：

```css
--bg:#080c11; --panel:#111921; --border:#22303d;
--text:#e9f1f7; --muted:#7e93a6;
--accent:#f6b23c;      /* 工业黄，主操作与品牌 */
--ok:#36d399; --warn:#f5a623; --danger:#ef5b5b;
--cloud:#8ea8ff;       /* 云端路径专用，和本地绿色区分 */
```

设计取舍：

- **深色**：车间大屏、控制柜环境光复杂，深色底比白底耐看、不刺眼；同时让黄色告警和绿色「有据」更突出。
- **大写等宽小字**：品牌副标题、文档编号、分数用 `--font-mono`，营造仪表盘/工单的工程感。
- **背景网格**：`body::before` 用 48px 网格 + 径向遮罩，静止但不单调；纯 CSS，无图片请求。
- **字号**：正文 16px，聊天正文 15.5px、行高 1.75，一线工人戴手套/远距离也能读；移动端不缩小字号。
- **状态色语义固定**：绿=本地/有据，蓝=云端/通用建议，黄=警告，红=危险/错误，不在别处混用。

## 4. 问答视图（ChatView）

### 4.1 SSE 消费

`lib/api.ts` 用 `fetch` + `ReadableStream` 手写 SSE 解析，而不是 `EventSource`：

- `EventSource` 只支持 GET，问题要放在 URL 里，长问题会超长且暴露在日志；
- 需要 `POST` + JSON body + `AbortController` 中途停止；
- 解析按 `\n\n` 分块，处理跨 chunk 的半截 JSON；单个事件解析失败只跳过该事件，不打断整条流。

事件处理对应 `meta → route → delta → done/error`：

| 事件 | 界面动作 |
| --- | --- |
| `meta` | 立刻显示引用卡片、路由标签、检索分数；答案区显示「正在生成」 |
| `route` | 本地切云端时，标签从绿色变蓝色，并出现切换原因 |
| `delta` | 追加正文，记录首字时间 |
| `done` | 用完整答案覆盖增量（防止漏字），落最终路由/拒答/来源，停止计时 |
| `error` | 显示错误卡片，保留已生成内容并标注可能不完整 |

### 4.2 引用卡片与正文联动

- 正文里的 `[1]` 由 `marked` 渲染成 `<sup data-cite="1">`；点击后滚动到对应 `SourceCard` 并高亮。
- 引用卡片展示：序号、文档名、文档编号、类别、章节路径、相似度、原文片段（可展开）。
- `sources` 与提示词编号同源（后端生成），前端不做字符串匹配，避免「引用对不上」。
- 拒答时后端把 `sources` 置空，界面只显示拒答说明，不会出现「拒答 + 一堆出处」的矛盾。

### 4.3 自动滚动

流式生成时跟随底部；生成结束后调用 `focusLastExchange()`，把**最后一条用户消息**滚到视口顶部。原因是引用卡片通常比答案长，如果继续贴底，答案会被顶出屏幕，用户只看到一堆出处。这个细节是实际演示时发现并修的。

### 4.4 路由标识

`RouteBadge` 三种状态：

- 绿色「本地模型 · 知识库作答」；
- 蓝色「云端模型 · 通用建议」；
- 灰红「已拒答 / 无依据拒答」。

标签旁显示模型名、首字耗时、总耗时；右侧栏显示本次 top-1 分数与阈值（如 `78% / 60%`），观众能直观看到「为什么走这条路」。

### 4.5 输入区

- 多行 `textarea` 随内容自动增高（上限 160px），`Enter` 发送、`Shift+Enter` 换行；
- 生成中发送按钮变为「停止」，调用 `AbortController.abort()`；
- 顶部模式开关 `auto / kb_only`，旁边一行小字解释两种模式的区别；
- 空状态给 4 个示例问题（开机检查、温度异常、飞边、触电应急），点一下直接提问，演示不用现场打字。

## 5. 诊断视图（DiagnosisView）

- 左侧步骤轴：已完成步骤打勾、当前步骤高亮、未走到的分支灰显；
- 中间问题卡：题干、提示、每个选项带 `tone` 色条（安全/警告/危险），下方折叠展示「手册依据」原文；
- 右侧进度：已答步数、预计步数、当前主题；
- 支持「上一步」回退，回退后清空结论，重新走分支；
- 完成态渲染处置单：报告编号、设备、现象、逐步过程表、结论等级、处置建议、安全提示、引用清单；
- 「打印 / 导出 PDF」调用 `window.print()`；打印样式在 `@media print` 下切白底黑字，`@page { size:A4; margin:0 }` + 14mm 内边距保证版心，`break-inside: avoid` 防止表格行被截断；
- 「下载 Markdown」直接指向后端 `report.md`，网页、打印、Markdown 三种形态同源。

## 6. 知识库视图（KnowledgeView）

- 顶部统计卡：文档数、切片数、类别数、当前阈值（全部来自 `/health` 与 `/api/kb/documents`，不写死）；
- 文档表：编号、标题、类别、版本、切片数、导入时间、操作；
- 操作：全量导入、重建索引、上传 `.md/.txt`、删除（二次确认，源文件进 `.trash`）；
- 检索测试台：输入问题 → 显示 top-4 片段、相似度、是否过阈值；演示时现场改问题，让评委看到分数如何变化；
- 所有异步操作有 loading、成功 toast、失败原因（后端 `detail` 原样展示），不吞错。

## 7. 响应式与可访问性

- 断点 1100px / 760px：三栏诊断变单栏，问答右侧信息栏折叠到答案下方；
- 390×844 实测无横向溢出，导航仍可点，输入框不被键盘遮挡；
- 所有按钮有 `type`、`aria-label` 或可见文字；状态不只靠颜色，配文字（「已拒答」「云端」）；
- `prefers-reduced-motion` 下关闭滚动动画（后续可加，当前动画都很短）。

## 8. 构建与部署

```bash
cd frontend
npm ci
npm run build      # 产物 dist/
```

生产环境由 FastAPI 托管 `frontend/dist`（`app/main.py` 挂载静态目录），因此只有一个 8000 端口、无跨域；Nginx 只做反向代理和 SSE 关缓冲。开发时 Vite 代理 `/api` 与 `/health` 到 `127.0.0.1:8000`。

## 9. 取舍与后续

| 选择 | 取舍 |
| --- | --- |
| 不引 UI 框架 | 视觉独特、包体小；组件要自己维护，开发量更大 |
| hash 路由 | 零依赖、刷新可恢复；没有嵌套路由和过渡动画 |
| KeepAlive | 切页不丢状态；内存占用略高，三页规模可忽略 |
| fetch 手写 SSE | 支持 POST/中断/自定义头；需自己处理分块边界（已处理） |
| 打印用浏览器 | 零依赖、A4 版式可控；不同浏览器字体略有差异，已在 Chrome 验证 |
| 前端不做答案校验 | 引用由后端同源生成；逐句核对属于后续增强 |

## 10. 答辩可能被问到的问题

- **为什么不用 Element Plus？** 评分里前端工程占 25 分，套模板很难体现设计；自建令牌系统能保证三个页面视觉一致，也方便按车间场景调字号和对比度。
- **SSE 为什么不用 EventSource？** 需要 POST 传长问题、需要中途停止、需要自定义 JSON 事件；`fetch` 流都能做，代价是自己解析分块。
- **流式过程中切云端，界面怎么处理？** 后端先缓冲本地拒答，确认切云端才发 `route` 事件；前端收到后改标签和来源，用户不会看到「拒答又变答案」的闪烁。
- **打印为什么能保证 A4？** `@page` 定义纸张，处置单自身加 14mm 内边距，表格行 `break-inside: avoid`；已用 Chrome `Page.printToPDF` 实测两页无裁切。
- **移动端能用吗？** 390×844 实测三个视图都可操作，无横向滚动；诊断三栏自动变单栏。
